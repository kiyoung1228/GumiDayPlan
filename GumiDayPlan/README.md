# 구미에서 뭐하지? — GUMI DAY PLAN

**구미시 공공데이터 기반 당일치기 코스 자동 추천 · AI 취향 분석 · 최적경로 탐색 시제품 (2026-11-07)**

사용자의 목적(데이트/친구/가족/관광/혼자), 분위기, 시간, 예산과 출발지를 입력받아 **관광지+식사 장소 후보를 선택**하고 **한정된 당일 일정 내 이동 순서를 최적화**하는 로컬 웹앱입니다.

> **검증 상태**: 로컬 백엔드+시연 데이터 통합 테스트 완료. 제공받은 실제 CSV 88건 로딩 완료. **실제 TourAPI/NAVER/Gemini 계정의 라이브 인증 호출은 키가 여기에 없으므로 미검증**입니다. 이 차이를 명확히 구분해 주세요.

## 1. 가장 쉬운 Windows 실행 방법 — `main.py`만 실행

1. ZIP을 압축 해제한 후 **`GumiDayPlan` 폴더**를 VS Code에서 엽니다.
2. `.env.example`을 **복사**해서 `.env` 파일을 만들고, 본인의 새 API 키를 입력합니다.
3. **`main.py`를 연 뒤 오른쪽 위 `▶ Run Python File`**을 누릅니다. (기존 `실행하기.bat` 사용 불필요)
4. 첫 실행 시 프로젝트 내부의 `.venv`를 자동 생성하고 `requirements.txt` 패키지를 설치합니다. **설치 시 인터넷 연결 필요**.
5. 웹 브라우저에서 자동으로 `http://localhost:8000/` 주소가 열립니다. 자동으로 열리지 않으면 주소를 직접 입력하세요.

**주의:** VS Code Python 파일 실행은 반드시 이 폴더의 `main.py`여야 합니다. `src/` 내부 파일은 직접 실행하지 않습니다.

패키지 설치를 따로 하고 싶을 경우 (이미 설치된 Python 환경 사용):

```powershell
cd C:\Users\user\Downloads\GumiDayPlan_사용자화면_개선\GumiDayPlan
python -m pip install -r requirements.txt
python main.py
```

`main.py`는 자동으로 프로젝트 전용 `.venv`로 전환합니다. 자동 설치를 사용하지 않고 직접 개발하려면 아래처럼 실행할 수도 있습니다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

**NAVER 지도 인증:** Maps 콘솔에 Web 서비스 URL을 `http://localhost`로 등록했다면 브라우저 주소도 **`http://localhost:8000/`** 여야 합니다. `127.0.0.1`은 다른 호스트명이므로 네이버 지도에서 인증 오류가 날 수 있습니다. 다른 환경에서 `127.0.0.1`을 사용하려면 Maps 애플리케이션에 `http://127.0.0.1`도 추가 등록하세요. 포트 번호는 등록하지 않습니다. **지도 인증 오류가 발생하면 OpenStreetMap으로 자동 전환**하며, 네이버 자동차 길찾기 기능의 인증은 별도로 확인해야 합니다.

**서버 종료:** 터미널에서 Ctrl+C. **`ModuleNotFoundError: fastapi`** 오류를 방지하기 위해 프로젝트 전용 `.venv`에 의존성을 자동 설치하도록 변경했습니다. `.env` 저장 후 서버를 다시 실행하세요.

## 2. API 키 매핑

| .env 항목 | 어디서 얻나 | 역할 |
|---|---|---|
| `PUBLIC_DATA_SERVICE_KEY` | data.go.kr 관광공사 TourAPI 2.0 활용신청 키 | 관광 명소 목록, 구미 음식점 API |
| `NAVER_MAP_CLIENT_ID/SECRET` | Naver Cloud > Maps | Dynamic Map, Directions 5, Geocoding |
| `NAVER_SEARCH_CLIENT_ID/SECRET` | Naver Cloud > NAVER API HUB | 별도 원본 지역 검색 화면만 |
| `GEMINI_API_KEY` | Google AI Studio | 공공데이터 장소의 선호도 평가 |
| `GEMINI_MODEL` | 계정에서 실제 사용 가능한 모델 | 기본 `gemini-3.1-flash-lite`, 변경 가능 |

**중요!**: 사용자가 이전 대화 스크린샷에 NAVER 및 공공데이터 키를 노출한 적이 있으므로, 그 키는 **재발급/교체한 뒤 사용**하세요. 본 소스 ZIP에는 어떤 키도 포함되지 않습니다. 브라우저에는 지도 JS SDK에 필요한 **Maps Client ID만** 전송하고, 모든 Secret은 서버 환경변수에만 보관합니다.

> API 사이트가 `서비스키`를 인코딩된 문자열로 제공해도 `.env`에는 **Decoding(일반) 키를 우선 입력**하세요. 인코딩 키도 프로그램이 `%` 디코딩을 한 번 시도합니다.

## 3. 처음 화면부터 실제 공공데이터로 코스 만들기

1. 첫 실행은 실제 장소 데이터 모드입니다. 관광지와 음식점 데이터 및 좌표를 먼저 확보하세요.
2. 개발 PC에서 `http://localhost:8000/?admin=1`로 접속한 뒤 `데이터 관리` → `관광 데이터 불러오기`. 한국관광공사 법정동 코드를 **실제 API**로 조회해 구미시로 필터링하고, 좌표가 있는 장소를 SQLite에 저장합니다.
3. 모범음식점 CSV 88건은 자동으로 등록됩니다. 좌표가 없는 업소는 `누락 좌표 채우기`에서 Naver Geocoding을 필요한 만큼 **명시적으로** 요청하세요.
4. 추가로 필요하면 구미시 일반음식점 API를 가져올 수 있습니다. 처음에는 120건 이하를 권합니다.
5. `코스 만들기`로 돌아가 취향/시간/예산/출발지 지정 후 실행하세요.
6. Gemini 키가 없거나 API 장애가 있으면 자동으로 **명시된 규칙 기반 추천**으로 전환됩니다.

`데이터 관리` 수집은 개발 PC의 운영자 화면에서 개별 버튼을 눌러야 호출됩니다. 자동 경로 계산은 코스 생성 때마다 NAVER Directions API를 호출할 수 있으니 별도 과금 및 호출 한도를 확인하세요. 앱 내부 과금 확인 팝업은 표시하지 않습니다.

## 4. 실제 구현 범위

- **공공데이터:** 실제 `경상북도_구미시_모범음식점 현황_20260409.csv` 88행(사람이 제공한 CSV) 탑재. 관광공사 TourAPI `ldongCode2` + `areaBasedList2`, 구미시 일반음식점 `getGnrlRstrt` 연동 코드 작성. 결과가 확인되기 전에는 실제 구미 장소 건수라고 주장하지 않습니다.
- **AI:** Gemini 모델은 *공공기관 데이터에서 가져온 후보*만 점수화하여 `ID/적합도/이유`를 JSON으로 돌려줍니다. 새 장소나 허위 요금·영업시간·별점 생성 금지. 실패 시 규칙 기반 점수.
- **코스 선정:** 사용자 제약(최대 방문 수, 전체 시간, 설정 예산)을 고려해 점수·유형 다양성·이동시간으로 빔 탐색(beam search) 수행. **가격이 없는 장소에는 사용자가 직접 설정한 식사/카페/기타 1곳당 지출 배정액**을 사용합니다. 이는 실제 가격 정보가 아니며, 실지출·예산 준수는 보장하지 않습니다.
- **방문 순서:** 동일한 장소 집합에서 최대 6곳의 **모든 순열**을 비교해 이동시간이 가장 짧은 순서로 정렬. 비교 막대는 *기존 점수순 방문 vs 최적 방문*의 **동일 집합** 비교입니다.
- **경로시간:** 코스를 만들 때 기본으로 NAVER Directions 5를 사용하며, 후보 최대 6곳에 대해 최대 42번의 자동차 경로 질의 (일부 실패는 추정값으로 표시). **도보/대중교통 지원하지 않음.**
- **지도:** NAVER Dynamic Map SDK(등록된 localhost origin 필요), 실패 시 OSM Leaflet 대체. 실제 길찾기 성공 경로와 단순 직선 근사를 시각적으로 구분(검증 항목).
- **수정:** 장소 제외 후 재계산. CSV 저장·인쇄. Map 클릭으로 출발지 선택.

### 중요한 제한

- 모범음식점 CSV와 일반음식점 API는 **실제 메뉴가격, 영업시간, 별점, 리뷰 수, 좌표를 제공하지 않습니다.** 값을 만들어 넣지 않으며 가격/운영시간 **미확인** 표기. 대신 사용자 입력의 **계획 예산 배정액**을 사용해 코스 조합을 제한하며, 실제 지출은 보장하지 않습니다.
- 공공데이터의 등록 여부 ≠ 현재 영업 중. 실제 방문 전 별도 확인 필요.
- NAVER 실제 자동차 경로 API 요청에 실패한 구간은 직선거리 기반 추정으로 표시됩니다. 이용량과 과금은 API 제공 서비스에서 별도 확인하세요.
- **NAVER API HUB 지역 검색 결과**는 서비스 이용조건상 **AI 입력·영구저장·추천 점수 산출에 사용하지 않습니다**. 독립된 검색 화면에서 원본 순서와 출처를 표시하고 상세정보로 연결합니다. 이 제한 때문에 관광 공공데이터+구미시 CSV가 주 추천 엔진의 장소 후보입니다.
- 구미시민·관광객 이용을 위한 연구 시제품이고 구미시 운영 공식 서비스가 아닙니다.

## 5. 공모전 기술 근거 및 평가 방법

**문제:** 취향과 시간·예산·이동수단에 맞춘 구미 당일 일정은 관광명소/식당을 개별로 찾고 이동 순서를 계산해야 함.

**해결:** 관광공사·구미시 공공데이터 기반 실제 장소 후보를 확보 → Gemini 선호 적합도 평가 → 시간·예산 제약으로 방문 장소 선정 → 동일 집합 최단 순서 계산 → 지도/일정표 제공.

추천 모델의 성능은 실제로 여러 사례를 테스트하기 전에는 주장하지 않습니다. 아래 지표를 동일 조건에서 수집하면 좋습니다.

| 실험 | 측정 | 기준 |
|---|---|---|
| 추천 모델 A/B | 사용자가 선택한 목적·취향에 맞는 장소를 얼마나 고르는가 | 사람 평가 점수, 장면별 10회 이상 |
| AI 효과 | 규칙 기반 vs Gemini 추천의 사람이 평가한 적합도 | 동일 장소 후보·시드·시간 예산 |
| 경로 최적화 | 동일 장소 집합, 점수순 vs 최적 순서의 이동시간 | 같은 이동시간 행렬(추정 또는 실제) |
| 실행 가능성 | 후보 주소, 이동시간, 출발시간, 확인된 운영시간, 미확인 필드 | 출처/조회일 구분 |
| 비용 | Gemini 입력/출력 토큰 및 NAVER API 호출 횟수 | 각 서비스 공식 요금 및 실제 사용로그 |

### 독창성 표현 제안

"공공데이터를 활용한 *구미시 일상 여가+관광 통합형* 당일치기 추천, 사용자 목적 기반 장소 선정과 시간제약 경로 최적화를 분리해 구현, 장소 제외 시 재추천, 기존 순서 대비 개선값을 동일 장소 집합으로 비교 가능". 단, 기존 서비스 대비 우월성은 실제 비교 검증 후에만 주장하세요.

- 상세한 프롬프트는 `docs/AI_추천_프롬프트_및_검증규칙.md` 참조.

### 업데이트할 때 공공데이터 좌표를 유지하려면

**기존 프로젝트의 `.env`뿐 아니라 `data/gumi.db`도 새 `GumiDayPlan` 폴더에 복사**하세요. `gumi.db`를 복사하지 않으면 이전에 TourAPI에서 모은 관광지나 지오코딩한 음식점 좌표를 다시 가져와야 합니다. 프로젝트 ZIP 안에는 사용자의 키·DB가 포함되지 않습니다.

소스 변경 후 **실행 중인 서버를 Ctrl+C로 종료하고 새 `main.py`를 실행**하세요. 웹 화면에 예전 결과가 남아 있다면 새 코스를 다시 생성하고 브라우저에서 Ctrl+Shift+R로 새로고침하세요.

## 2026-11-09 사용자 화면 개선 (공개용 UI)

- 네이버 지역검색 API가 응답하는 `<b>...</b>` 강조 태그를 검색 결과에서 제거했습니다. 검색 제목/분류/주소는 HTML로 실행되지 않도록 다시 이스케이프합니다.
- 코스 만들기 화면에서 **Gemini 취향 평가**와 **NAVER 실제 자동차 경로 최적화** 체크박스를 제거했습니다. 두 기능은 코스를 만들 때 **항상 활성화하여 요청**합니다. 무료 API 사용 보장이나 실제 호출 성공을 뜻하지는 않습니다. 인증정보가 없을 경우 오류를 표시하고, Gemini 장애 등은 기존 추천 엔진의 대체 로직이 적용될 수 있습니다.
- 기존 `confirm(...)` 방식의 Directions/주소변환 **과금 확인 팝업을 제거**했습니다. 자동 경로 요청은 `.env`의 `MAX_DIRECTIONS_CALLS` 상한(기본 42회/코스) 내에서 수행되며, 사용량/과금은 서비스 계정 설정에서 별도로 관리해야 합니다.
- 일반 사용자에게는 개발 중 안내, '실제로 구현한 범위와 한계' 카드, 내부 데이터/설정 설명, 가상 데이터 시연 체크박스를 표시하지 않습니다. 실제 가격/운영시간 미확인 및 추정 이동시간 등 방문에 필요한 사실은 계속 표기합니다. 가상 시연 자료는 코스 생성에 자동으로 사용되지 않습니다.
- **운영자용 데이터 관리**는 일반 내비게이션에서 숨겼습니다. **개발 PC에서만 `http://localhost:8000/?admin=1`** 주소로 접속하면 `데이터 관리` 탭이 나타납니다. 여기서 관광정보 수집과 누락 좌표 보완을 계속 할 수 있습니다. `?admin=1`은 화면 표시 전용이며, 공개 서버에 배포하려면 관리자 인증 및 API 접근 제어를 별도로 구현해야 합니다.
- 새 압축파일에는 `.env` 및 개인이 수집한 `data/gumi.db` 파일을 포함하지 않습니다. 기존 파일을 새 폴더에 복사하세요. API 키가 포함된 `.env`는 공유하지 마세요.
